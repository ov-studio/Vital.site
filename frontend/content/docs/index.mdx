## Overview

**Vital.sandbox** is an open-source, high-performance sandbox built on Godot-Engine and powered by C++17 & Lua.
<br/>Full control over rendering, networking, threading, and assets - one seamless workflow

Gameplay, UI and server logic are written in **Lua**, while the engine handles rendering, physics, networking and asset delivery. Windows is supported today, with Linux, macOS, Android, iOS and Web planned.

Four core principles drive everything under the hood:

- **Performance-first** — Lean by design. No bloat, no unnecessary abstractions. Nothing stands between your scripts and the core.engine.

- **Modular by nature** — A strict C++17 module system. Use only what you need, extend what you want, and leave the rest untouched.

- **Built for developers** — Async/await, promises, heartbeats, and event-driven patterns — modern concurrency without sacrificing low-level control.

- **Open at the core** — No licensing fees, no royalties, no restrictions. What you build is entirely yours.

## Lua scripting in Godot

Scripts live inside **resources**. A resource is a folder under the server's `resources/` directory, described by a [`manifest.yaml`](/docs/resource/manifest) that lists its scripts and files.

```txt title="Example resource folder"
resources/
└── hello/
    ├── manifest.yaml
    ├── server.lua
    └── client.lua
```

```yaml title="resources/hello/manifest.yaml"
name: "Hello"
author: "YourName"
version: "1.0.0"

scripts:
  - { src: "server.lua", type: "server" }
  - { src: "client.lua", type: "client" }
```

Server scripts run on the dedicated server, client scripts run on every connected player, and shared scripts run on both. Clients download a server's resources automatically when they connect.

Scripts communicate through [events](/docs/event/on). A client can only trigger a server handler that was registered with `remote = true`, and the handler receives the sender's peer id in the `client` variable.

```lua lineNumbers title="server.lua"
util.event.on("hello:request", function(message)
    core.engine.print("info", "Player " .. client .. " says: " .. message)
end, { remote = true })
```

```lua lineNumbers title="client.lua"
util.event.emit("hello:request", { remote = true }, "Hello from Lua!")
```

Resources do not share a global environment. Each one gets its own copy of the root global tables, so changing a shared table such as `string` or `math` in one resource does not affect the host or any other resource.
