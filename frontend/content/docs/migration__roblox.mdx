## Overview

Roblox is a consumer game platform, not a server framework. Its discovery engine, social graph, and monetization infrastructure exist entirely within the Roblox platform — players find your experience through the Roblox app, not through a direct connection.

A Vital.sandbox server is a standalone application. Players connect via a master list or direct IP. There is no equivalent of the Roblox game page, avatar marketplace, or in-platform friend invite system. If your experience's value comes from the Roblox audience, migrating loses that entirely. If your experience is primarily a game with custom systems and you want full engine control, self-hosting, and no platform cut, Vital.sandbox is a viable target.

## What carries over

Roblox uses Luau, a typed superset of Lua 5.1. Most scripting logic — tables, functions, closures, coroutines — translates directly once you adapt to the API surface:

| System | Roblox | Vital.sandbox |
|--------|--------|---------------|
| Events | `RemoteEvent` / `BindableEvent` / `:Connect` | `util.event.on` / `util.event.emit` — remote firing, async callbacks, priority ordering |
| Timers | `task.delay` / `task.spawn` / `task.cancel` | `util.timer` — create, start, stop, reset |
| HTTP | `HttpService:GetAsync` / `PostAsync` | `util.http.get` / `util.http.post` — headers, timeout |
| Database | `DataStoreService` — Roblox-managed cloud | `core.database` + `core.database_query` — MySQL, self-hosted, async execution |
| 3D Models | `Model` / `MeshPart` + Roblox CDN | `core.model.create` — GLB, animation, bones, blendshapes, material overrides |
| Vehicles | Custom VehicleSeat rigs | `physics.vehicle_body` + `physics.vehicle_wheel` — engine force, brake, steering, velocity, impulse, CCD |
| UI | ScreenGui / BillboardGui / SurfaceGui | `core.webview` (HTML/CSS/JS), `core.canvas` (2D draw), `core.rendertarget` (texture render) |
| Audio | `Sound` objects attached to parts | `core.audio_2d` / `core.audio_3d` — volume, pitch, FX chain, spatial attenuation — OGG, WAV, MP3 |
| Images | Roblox CDN textures | `core.image` / `core.svg` — JPG, PNG, WEBP, BMP, DDS, KTX, EXR |
| File I/O | None built-in | `util.file` — read, write, hash, delete |
| Networking | Roblox replication layer | `ISyncable` net IDs, `core.engine.get_entity_by_net_id`, server-authoritative replication |
| Async scripting | `task` library / coroutines | `util.thread` + `util.promise` — yield on await, resume on resolution |

## What does not carry over

- **Roblox assets** — marketplace models, `.rbxm` files, avatar items. Models must be exported to **GLB** and re-imported. Images must be exported to a supported format. This is a manual process per asset.
- **Luau type annotations** — Vital.sandbox uses standard Lua. Luau-specific syntax (`string`, `number`, `::` casts, `--!strict`) must be removed.
- **Roblox services** — `Players`, `ReplicatedStorage`, `ServerStorage`, `Workspace`, `TweenService`, etc. are Roblox-specific. The underlying patterns all have equivalents in Vital.sandbox but require explicit reimplementation.
- **Avatar system** — Roblox's avatar pipeline, character appearance, and R6/R15 rigs are platform-proprietary. Characters must be implemented with your own GLB assets.
- **In-platform discovery and monetization** — there is no replacement for the Roblox storefront, Robux, or the game page. These are platform features, not engine features.
